# EXOKEMET implementation outcomes

- [ ] **Mission-led home and direct access:** The responsive landing page explains EXOKEMET's purpose, research value, scientific scope, and key limitations without implying NASA endorsement. Visitors can open the explorer directly without login, OAuth, or database.
- [ ] **Discovery map, filters, and search:** The responsive Leaflet global discovery map uses the supplied map logic and candidate data; Moon/Mars filters, location search, candidate markers, informative popups, legend, map controls, and desktop/tablet/mobile interactions work.
- [ ] **Candidate profiles and supplied imagery:** Selecting a candidate updates the hero backdrop using the supplied White Desert, Black Desert, and Umm Jirsan imagery. Site profiles show site name, coordinates, Earth location, target environment, available characteristics, evidence, sources, confidence, limitations, and clearly state when similarity is not calculated; approximate or pending coordinates remain prominently labeled.
- [ ] **Discovery triage and scientific comparison:** Hidden Earth Site Discovery presents editorial-triage ordering and preliminary/unverified labels without fabricated similarity scores. Moon and Mars comparison views show available values with units and sources, explicit limitations, and unavailable states rather than inferred measurements.
- [ ] **Methodology, sources, and scientific boundaries:** Methodology and source registry explain feature extraction, mission lenses, provenance, unavailable values, and boundaries of analog comparison. Distinguish illustrative/demo, unverified, unavailable, and real content. State that similarity does not establish landing/base suitability and does not reproduce lunar gravity, vacuum, radiation, or the full Martian atmosphere.
- [x] **Site-photo candidate profile requested by user:** Replace the blue/navy profile header shown in the supplied reference with a wide photograph of the selected candidate's actual site, and place the candidate name and profile information beneath the image. Use the supplied White Desert, Black Desert, and Umm Jirsan photos as appropriate; keep tabs, data, warm dark content surfaces, readable contrast, amber/gold active states, and responsive behavior.
- [x] **Real planetary-photo orbit graphic and motion requested by user:** The Earth, Moon, and Mars in the orbit graphic use real photos instead of the current illustrated icons. Keep the images correctly associated with their orbit labels and bundle them locally so they work in the Visual Studio Code project and after the user later uploads it to GitHub; document the NASA image sources and credits. Animate all three bodies in distinct orbital paths, speeds, and directions; keep distinct static positions when the system requests reduced motion, and label the paths as illustrative / not to scale.
- [x] **Architecture, serving, and assets:** Preserve the React + Vite architecture, current data modules, Leaflet map, supplied assets, separation of data and presentation, static serving, Docker support, and unauthenticated `/health` endpoint. The route manifest declares the page routes.
- [ ] **Accessible responsive interactions:** Navigation, filters, tabs, search, and buttons remain functional with keyboard/screen-reader interactions and graceful empty/error states.
- [x] **Build and delivery notes:** The site builds and serves on the project runtime; document remaining scientific work, assumptions/demo data, and run instructions in the handoff materials.
